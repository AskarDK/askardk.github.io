01 / CONTEXT

The challenge

Food, activity and training data can become scattered across disconnected tools. The application's goal is to connect them to one profile and create a coherent journey between actions.

02 / DEVELOPMENT

My work

Web application development: backend routes, data models, user interfaces, AI features and Telegram integration.

  • Data models for users, groups, training sessions, food logs and activity.
  • Separate member, trainer and administrator workflows.
  • AI-powered meal-plan generation and food-photo analysis.
  • A training schedule and participant registration.
  • Linking Telegram accounts to the application and sending reminders.

04 / ENGINEERING

Engineering decisions

01

One profile across workflows

Food, measurements and training belong to the same user. This makes it possible to preserve history and move between application sections.

02

Roles shape the interface

A member needs a personal diary, a trainer needs groups and scheduling, and an administrator needs application management.

03

Telegram as part of the product

The bot and reminders extend the web interface, working with a linked user profile rather than a disconnected account.

What this case covers

This case focuses on application architecture and user journeys. It makes no claims about medical effectiveness, AI accuracy or verified hardware integrations.
